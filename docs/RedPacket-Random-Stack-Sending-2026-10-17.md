# 红包地图资源自动挑堆发送（2026-10-17）

## 明确的业务选择

用户要求仿照原版操作：普通资源同类汇总显示，输入总量后自动挑堆凑足，一个逻辑红包。用户进一步明确选择“允许统一为随机选中一堆的状态”。这是本轮业务语义授权，不再沿用前一份可行性报告的“不同状态须先保持等价”的暂定建议。

发送的物品采用随机选中来源堆的一份完整状态（包括耐久、腐败进度及其他完整序列化字段）；不是平均状态或多数状态。没有提前修改或物理合并原物品，也不会修改未选中的物品堆。未领取部分仍按原机制保留/返还原物品，不为返还额外重写原状态。

## 本轮实现范围

- **已接通地图实物多堆**。`RedPacketItemChoice.CreateSelection` 汇总当前商品行的所有地图来源 Thing，交给同一个 `RedPacketAvailableItem` / `StackedThings`。数量可以超过单个物品堆；实际发送仍只进入一次 TrySendPacket，创建一个 PacketId，保留用户输入的领取份数。
- 发送前 `PreparePhysical` 对来源随机洗牌，按顺序挑足数量。最后一堆仍由原取物逻辑只分出所需部分；模板取随机队列第一堆的完整状态，并以本次总量生成单模板。只在实际发送时随机一次，不随绘制或键入改变。
- 使用插件私有 System.Random，不消耗 Verse.Rand。测试通过注入随机索引固定来源顺序，真实随机仍由生产代码负责。
- 普通资源不再要求完整状态一致或按状态数量占比选择主模板；保持相同实际 Def/材质，界面仍按品质/样式分隔变体。
- 武器、护甲和其他不适合自动归组的物品单列；即便 Mod 调大装备 stackLimit，也不会因此将多个装备对象自动组合发送。
- 原数量/重复来源/已销毁等检查、发送前合法交付上限、物品原点恢复、入队拒绝处理、领取回执和结果未知语义保留。原 1000 堆保护约束实际选中来源/交付数量，不因为候选来源池超过 1000 就拒绝只发送少量物品。
- 原公共确认中增加简短状态说明，沿用公共主题/renderer/action/confirmation，没有新增第二个确认弹窗或私有 Draw。
- 组合选择由 owner 显式绑定，刷新/换存档释放后旧组合失效；实时可用数量变化会刷新表单与动作。未把尚未注册的组合绕过 freshness 检查。

### 未扩写为已完成的范围

库存多 EntryId 与地图/库存混合事务尚未接通。地图和库存同时有同类物品时，商品行保留汇总，并明确本次可发地图数量；不会拿总余额冒充地图可发量。只有多库存来源的项仍提示分别发送；单库存记录沿用原流程。该限制来自现有库存预留/托管路径，本轮没有通过不登记预留、丢失来源或复制物品绕过。

本轮按当前反馈的地图化合燃料/石块场景实施。不能把地图多堆通过写成所有库存混合来源事务已实现。

## 链路与验证证据

`商品行 → PresentationSelectChoice → 合并地图来源选择 → 输入总量 → TrySendPacket 一次 → PreparePhysical 随机来源/状态模板 → PopSelectedWithOrigins 按总量取物 → 单 PacketId / StoredThings → 原广播与领取/返还`

- 46 组 source-linked 业务算法场景通过。覆盖不同状态来源随机模板、40 种固定随机种子的数量守恒、装备修改上限仍拒绝跨件、无效随机索引拒绝、1001 个候选来源只取少量、序列化异常恢复临时数量、来源重复/不足、合法交付拆堆与既有通知去重。
- 14 项 source-linked 商品归类检查通过，包括 120 堆 × 750 合为一行 90,000、组合选择总量、装备单列、来源标记、品质/材质/样式隔离、大计数不溢出。
- 最终交付 DLL 的两版各 44 项红包公共呈现绑定检查通过。新增真实类检查：两个各 750 的 Thing 分为一个商品行，owner 绑定组合后可设置 1000，组合可被当前动作识别，清空/刷新后失效，浏览过程不扣物品。游戏 Thing/owner 通过隔离夹具初始化，未执行原生世界/Scribe。
- 两版各人才 86、商店 109 项消费者回归通过。两个实际 ZIP variant 对上轮主 Mod 精确 DLL 的预检均 hostReferencesChecked=true。
- 两版插件完整源码对上一份已交付 Host（库存计划修正 ZIP）构建通过；不引用另一任务正在更改的 Framework/Trade 源码。1.7 保留两项原有 WebRequest obsolete 警告。
- 版本 0.0.6 是新的本地不可变候选；保留 0.0.4/0.0.5，不覆盖旧包。没有安装、提交、推送或发布。

上述是算法、元数据和真实类绑定检查，不是游戏实机验收。仍需验证真实化合燃料/石块 Scribe、最后一堆 SplitOff、广播、对方领取、超时返还及失败恢复。未声称原生端到端通过。

## 实机重点

1. 地图上同类资源有多堆且状态不同，只显示一个商品行；武器/护甲仍单列。
2. 输入超过单堆、低于总量的数量，设置领取份数，发送；只出现一个红包记录，物品总量和领取份数正确。
3. 发送者仅扣除所选总量，未选中堆保持原状态；接收物品统一采用被随机选中来源的状态，按合法堆上限交付。
4. 取物前来源被消耗/销毁、序列化失败或整批入队拒绝时，不能部分扣取却创建完整红包；未知结果不自动返还/重发。
5. 窄窗口/搜索/刷新/切换存档、数量变动、关窗及重复点击保留原 stale/去重规则。
